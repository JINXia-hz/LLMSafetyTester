# 流程追踪报告

> 本文档详细追踪一次完整评估（从 `python -m llmsec.pipeline.runner` 启动到退出）的每一个阶段、每一次 R 矩阵读写、每一个并发决策点。

---

## 概览

```
用户启动 runner
    │
    ├── Phase 0：准备（参数解析、攻击集加载、客户端初始化、目标列表确定）
    ├── Phase 1：快照（R + 特征，一次性获取，不可变）
    ├── Phase A+B：评估+报告（per-target，并发，不读活 R、不写 R）
    │     └── 每个目标 = 一个独立检测过程
    │           ├── run_attack_phase（Phase 1 攻击，读快照不读活 R）
    │           ├── run_allergy_phase（Phase 2 过敏）
    │           └── write runner_report.json（从 local tracker 生成）
    ├── Phase C：写入 R（主线程串行，所有评估完成后）
    ├── Phase D：清理（trackers → GC）
    └── 汇总日志
```

| # | 操作 | 读 R？ | 写 R？ |
|---|---|---|---|
| 0.1 | 解析 CLI 参数（`--phase`, `--input`, `--batch-size`, `--max-rounds`, `--targets`, `--target-concurrency` 等） | ❌ | ❌ |
| 0.2 | 全局种子注入 `set_global_seed(args.seed)` | ❌ | ❌ |
| 0.3 | 实验隔离模式：重绑 `RESULTS_FILE` / `ELO_CACHE_FILE` 路径到 `work_dir`（HPO trial 用） | ❌ | ❌ |
| 0.4 | 创建 run 目录 `runs/<时间戳>/`（秒级撞名时追加 `_2/_3`） | ❌ | ❌ |
| 0.5 | 加载攻击集 JSONL → `records` + `method_records` | ❌ | ❌ |

| 0.7 | 确定目标列表 `names`：`--target` → 单目标；`--targets` → 子集；默认 → 全部声明目标 | ❌ | ❌ |

### 目标列表解析逻辑

```
if --target X:           names = [X]
elif --targets A,B:      names = [A, B]
elif available_targets:  names = 全部声明目标
else:                    报错退出
```

`available_targets()` 调 `load_targets()`，后者扫描 `.env`：
- 有 `TARGETS=name1,name2` + `TARGET_<N>_*` 四件套 → 逐个注册
- 无 `TARGETS` 但有 legacy `TARGET_MODEL` 等 → 自动注册为一个声明目标（legacy fallback）

## Phase 1：快照

**代码位置**：`runner.py main():297-310`

### 步骤

| # | 操作 | 代码 |
|---|---|---|
| 1.1 | 加载 R 快照 | `R_snapshot = ResultsMatrix.load()` |
| 1.2 | 设方法清单 | `R_snapshot.set_method_catalog(catalog)` |
| 1.3 | 提取特征（一次） | `_feat_tracker.predictor.fit_features(records)` |
| 1.4 | 取出特征字典 | `features = _feat_tracker.predictor.artifacts.get("features", {})` |

### 关键不变量

- **`R_snapshot` 在整个评估期间不可变**——传入 `_eval_one_target` → `run_attack_phase` → `_inject_predicted_elos`，替代 `ResultsMatrix.load()`。
- **`features` 共享只读**——所有目标复用同一份方法级特征（特征是方法属性，与防御方无关）。

### 为什么需要快照

| 不用快照（旧） | 用快照（新） |
|---|---|
| `_inject_predicted_elos` 每轮 `ResultsMatrix.load()` → 读活 R | 读 `R_snapshot` → 读不可变副本 |
| 并发时目标 A 的 `publish_tracker` 可能正在写 R → 目标 B 读到半截数据 | 评估期间 R 零写入 → 无竞争 |
| 串行时目标 2 的 BlendPredictor 用了目标 1 刚写入的数据 → 跨模型污染 | 目标 2 的预测基于同一份快照 → 无污染 |

## Phase A+B：评估 + 报告

**代码位置**：`runner.py main():312-409`（`_eval_one_target`）+ `:411-450`（调度）

### 调度模型

```
调度单位 = 一个目标（name）
并发控制 = ThreadPoolExecutor(max_workers=target_concurrency)

target_concurrency=1（默认）→ 串行逐个
target_concurrency=N → N 个目标同时评估，其余排队
```

`ThreadPoolExecutor` 内部实现了：
- 排队就睡（`queue.Queue.get()` 阻塞，不 spin）
- 完成一个唤醒一个（worker 空闲 → 取下一个 task）
- 无需手写信号量/条件变量

### `_eval_one_target(name)` 内部流程

**完全不读活 R、不写 R。**

```
_eval_one_target(name)
│
├── 1. 创建 local tracker
│     tracker = ELOTracker()
│     tracker.predictor.artifacts = 共享特征（只读）
│
├── 2. Phase 1 攻击（run_attack_phase）
│     │
│     ├── 冷启动：_inject_predicted_elos(r_snapshot=R_snapshot)
│     │   ├── R 有 ≥2 模型 → BlendPredictor(R_snapshot, features)
│     │   │   └── 从快照训练统一/模型双层预测器，预测未测方法 Elo
│     │   └── R 有 <2 模型 → ClusterEloPredictor（tracker 自身 GT）
│     │
│     ├── D-optimal 种子选择 → 评估种子 → update_round（Model B 同步轮次）
│     ├── 记录防御指纹（per-seed Elo → 统一库 probes 表）
│     │
│     ├── 主循环（每轮）：
│     │   ├── 自适应 batch_size（收敛距离驱动：ci_half 大→大批，小→小批）
│     │   ├── 批内并行求值（ThreadPoolExecutor，concurrency 控制）
│     │   │   └── worker: set_active_target(name) + evaluate_single
│     │   ├── update_round（Model B：同步轮次，√N 缩放）
│     │   ├── record_round_end（轨迹点追加）
│     │   ├── _inject_predicted_elos（更新未测方法预测，仍用 R_snapshot）
│     │   └── check_convergence（CI + drift dual-threshold）
│     │
│     └── 最终聚类（post-test：HDBSCAN + auto-k + ANOVA 簇效验证）
│
├── 3. Phase 2 过敏（run_allergy_phase）
│     ├── 取 ELO 边界上下 N 个方法
│     ├── 获取/生成安全孪生 prompt
│     ├── 并行评估孪生（call_target）
│     └── 统计 FPR
│
├── 4. 报告（从 local tracker 生成，不读 R）
│     ├── tracker.save(run_dir / "state.json")
│     ├── 从 attack_results.jsonl 算 ASR
│     └── write_json(run_dir / "runner_report.json", {
│           target_model, security_level,
│           attack_phase: {asr, total_tested},
│           elo: {boundary_elo, ci_half, drift, converged},
│           allergy: {fpr, allergic}
│         })
│
└── 返回 (tracker, info)
      tracker → 供 Phase C 写入 R
      info → 供汇总日志
```

### 线程安全保证

| 共享资源 | 保护机制 |
|---|---|
| `R_snapshot` | 不可变（评估期间无人写） |
| `features` | 不可变（方法级特征，与目标无关） |
| `_feat_tracker.predictor.artifacts` | 只读共享 |
| `set_active_target(name)` | `threading.local`（每线程独立 ambient） |
| Judge 客户端 | OpenAI SDK httpx 连接池（线程安全） |
| 目标 API 客户端 | `_named_clients` 字典 + 双重检查锁 |
| `results` / `trackers` dict | **主线程统一写**（worker 只返回数据，`as_completed` 在主线程收集） |

### 并发深度

```
ThreadPoolExecutor(target_concurrency)          ← 目标级并发
  └── run_attack_phase 内部：
        ThreadPoolExecutor(concurrency)        ← 批内方法级并发
          └── evaluate_single → call_target → API 调用
```

总并发 API 调用 = `target_concurrency × concurrency`。例如 3 × 5 = 15 个并发 API 请求。

## Phase C：写入 R

**代码位置**：`runner.py main():452-465`

### 流程

```
Phase A+B 全部完成（所有目标的评估+报告都跑完）
    │
    ├── 主线程串行遍历所有目标：
│   for name in names:
│       tracker = trackers[name]
│       publish_tracker(tracker, name)
    │         │
    │         ├── _file_lock(RESULTS_FILE)       ← 文件锁，串行化
    │         ├── R = ResultsMatrix.load()        ← 读当前 R
    │         ├── R.upsert(tracker.history)       ← 合并该目标的全部观测
    │         ├── R.save()                        ← 原子写
    │         └── _save_cache(elo_cache)          ← 派生缓存（含收敛轨迹）
    │
    └── 全部写入完成
```

### 关键不变量

- **写入是串行的**（主线程 for 循环），即使 Phase A+B 是并发的。
- **每次 publish_tracker 在 `_file_lock` 内**（`elo_access.py:151`），防并发写损坏。
- **报告先于写入**（Phase A+B 的 runner_report.json 在 Phase C 之前生成），保证 R 不被半截评估污染。

### `publish_tracker` 做了什么

```
publish_tracker(tracker, name):
    with _file_lock(RESULTS_FILE):           ← 跨进程文件锁
        R = ResultsMatrix.load()              ← 读最新 R（可能含其它目标的刚写入数据）
        for h in tracker.history:             ← 遍历该目标的全部观测
            if h.defender == name:
                R.upsert(h.attacker, name, h.eval_score, extra={round: ...})
        R.save()                              ← 原子写

    derived = derive_elo(R, name)             ← 从合并后的 R 派生 Elo（纯函数）
    cache[name] = {                           ← 更新派生缓存
        fingerprint, attacker_ratings, defender_ratings,
        ground_truth, round_defender_elos, ...
    }
    _save_cache(cache)
```

## 存储结构

```
output/runs/<timestamp>/              ← 一次运行批次
├── <target-A>/                       ← 一个完整检测过程
│   ├── runner_report.json            ← 前端可读（报告生成后 finalize_run 入库）
│   ├── attack_results.jsonl          ← 攻击详情（含响应原文）
│   ├── allergy.json                  ← 过敏检测报告
│   ├── state.json                    ← tracker 快照
│   └── cluster_security_analysis.json ← 簇级分析 + 模型诊断
├── <target-B>/
│   └── ...
output/state/
└── catalog.db                        ← 统一库：observations 表（R 观测，
                                        Phase C 写入）+ elo_cache / probes 派生表
                                        + runs/trials/tasks 登记 + ctl_* 表
（per-target 快照 state.json 在各 run 目录内）
```

## R 矩阵读写时序

```
时间 →

Phase 0    Phase 1     Phase A+B           Phase C      Phase D
准备       快照         评估+报告            写入 R       清理
           │            │                    │
           │ 读 R ──────┼────────────────────┘
           │ (快照)     │ 不读活 R            │ 读+写 R
           │            │ 不写 R              │ (串行, 文件锁)
           ▼            ▼                    ▼
      R_snapshot    trackers[i]          R.merge(tracker_i)
      (不可变)      (local, 不碰 R)      for i in names (串行)
```

**R 在评估期间完全冻结**——读用快照、写延后到 Phase C。

---

## 崩溃恢复

| 崩溃时机 | R 状态 | 恢复能力 |
|---|---|---|
| Phase 0/1（准备/快照） | 未变 | 无损失，重启即可 |
| Phase A+B（评估中） | 未变（快照模型，不写 R） | attack_results.jsonl 每轮增量写 → 可看部分结果；R 干净，重跑即可 |
| Phase C（写入 R 中） | 逐目标 upsert | 每目标一个 SQLite 事务（BEGIN IMMEDIATE）→ 已写入的目标在 R 里，未写入的不在 |
| Phase D（清理） | R 已完整 | 无损失 |

### 与旧架构的对比

| 旧架构（每轮 publish） | 新架构（Phase C 统一写入） |
|---|---|
| 评估中途崩了 → R 有半截数据 → 重跑时 BlendPredictor 用了半截数据 | 评估中途崩了 → R 干净 → 重跑无副作用 |
| 并发时两个目标同时写 R → 文件锁排队但频繁 | 串行写入，逐目标单事务 upsert |

**取舍**：新架构牺牲了"评估中途看板能看实时进度"（R 不变直到 Phase C）。实时进度改为读 per-target 的 `attack_results.jsonl`（每轮增量写）。
