# 数据结构

> **对应代码版本**：P9 所有权翻转落地后（2026-08，`main` 分支）。
> **权威声明**：schema 的唯一定义处是 `llmsec/storage/models.py` 与 `llmsec/storage/rstore.py`；本文是可读镜像，与代码不符时以代码为准。
> 存储层的访问规则（DAO 收口 / AST 守卫 / 事务语义）见 `llmsec/storage/db.py` 模块文档。

---

## 1. 总原则：db 独占状态，文件只做三件事

所有**状态**（可变权威数据、事件流、登记、派生缓存的元数据）都活在 SQLite 里；
文件只剩三种合法角色：

| 角色 | 例子 | 为什么是文件 |
|------|------|--------------|
| 人读制品 | 报告 md/json、攻击明细 | 给人看 / 给工具渲染 |
| 大块 blob | 预测器 pkl、聚类产物、joblib | 体积大，db 只存元数据 |
| 进程通道 | `.log`、`.progress.jsonl`、`.env` | 流式 tail / 子进程直接读写 |

配套的写入纪律（P9）：

- **写入口全生命周期**：`register_*`（创建占行）→ `finalize_run`（报告落盘后一次富化）→ `remove_run`（软删删行）。runner / cli / task_manager 自己收尾。
- **查询纯读**：所有 `query_*` 是纯 SELECT——不扫目录、零变更不开写事务。
- **对账是显式恢复工具**：`reconcile_*` 只服务"手动拷贝/删除目录"这类旁路操作的事后矫正（`storage reindex` / `verify` / `migrate-layouts` / TUI legacy 视图 / workspace 历史采用），不在任何热路径上。

## 2. 统一库 `output/state/catalog.db`

全项目唯一数据库文件。SQLModel + SQLite（WAL，写事务 `BEGIN IMMEDIATE`，busy_timeout 5s）。
SQL/ORM 只存在于 `llmsec/storage/` 包内（AST 守卫强制）；外部一律经 `llmsec.storage.contract`，control 层经 `control.core.storage` 薄转发。

15 张表按域分组：

| 域 | 表 |
|------|-----|
| R 观测 | `observations` `runits` `rmodels` `elo_cache` |
| 登记 | `runs` `trials` `tasks` |
| 预测器 | `probes` `predictor_cache` |
| control | `ctl_events` `ctl_plans` `ctl_plan_meta` `ctl_tickets` `ctl_queue` `ctl_workspaces` `ctl_env_snapshots` |

### 2.1 R 观测域——评估体系的唯一不可重算状态

#### `observations`（R 矩阵）

| 列 | 类型 | 说明 |
|----|------|------|
| `record` + `model` | 联合 PK | 行键 = 实测记录 id；列键 = 被评模型名 |
| `eval_score` | float | 该记录对该模型的评分 |
| `status` | str | 观测状态 |
| `ts_json` | str | 时间戳的 `json.dumps` 原文——int `5` 与 float `5.0` 位级不同，保列指纹可复现 |
| `ins_order` | int | 入库序（时间轴回放用） |
| `extra` | JSON | 扩展位：`unit`（评级单位）、`round`（轮次）等 |

内存视图是 `core/results.py` 的 `ResultsMatrix`（load 全量构建），后端是 `storage/rstore.py`。
写入方：`publish_tracker`（评估结束 Phase C）、`upsert_observations`（merge / evaluator CLI）。
派生消费者：Elo（`derive_elo`）、BlendPredictor 训练、收敛轨迹、报告。

#### `runits` / `rmodels`

有序目录表：`unit`/`model`（PK）+ `position`。runner 在 publish 分支 `set_units`
落评级单位目录（merge 时 `all_units` 按此合并）；`rmodels` 同理记列序。

#### `elo_cache`

| 列 | 类型 | 说明 |
|----|------|------|
| `model` | PK | 被评模型 |
| `fingerprint` | str | 该模型列内容的 md5（列指纹） |
| `payload` | JSON | 派生好的完整 Elo 状态（含收敛轨迹），内嵌 `_version` |
| `updated_at` | float | 最后写入时间 |

命中条件：指纹匹配 + payload 版本号匹配。列内容变 → 指纹变 → 自动失效重算。

### 2.2 登记域

#### `runs`

| 列 | 类型 | 说明 |
|----|------|------|
| `name` | PK | `'批次/target'`（gen3）`'批次'`（gen1/2 扁平）或 target 名（卫星库） |
| `batch` / `target` | str | 批次时间戳目录名 / 目标名 |
| `layout` | int | 0=登记时无产物（进行中）2=扁平世代 3=`<ts>/<target>` 世代 |
| `dir_path` | str | run 目录绝对路径 |
| `mtime` / `registered_at` | float | 目录 mtime / 首登时间 |
| `target_model` / `security_level` | str | 从 runner_report 提取 |
| `has_report` `has_md` `has_tree` `has_cluster` `has_artifact` | bool | 产物存在位 |
| `size` | int | 目录字节数 |
| `metrics` | JSON | `extract_report_metrics` 提取的指标超集（asr / boundary_elo / …） |

生命周期：`register_run`（目录创建）→ `finalize_run`（报告后富化）→ `remove_run`（`execute_delete` 显式删行）。

#### `tasks`

| 列 | 类型 | 说明 |
|----|------|------|
| `task_id` | PK | `evaluate-<HHMMSS>-<rand>` 形态 |
| `kind` | str | evaluate / hpo / launchmeta … |
| `status` | str | queued → running → success/failed/cancelled |
| `registered_at` / `updated_at` | float | 首登 / 最后迁移 |
| `cmd` / `pid` / `log_path` / `started_at` | — | 进程通道锚点（PID 供跨进程探活/取消） |
| `meta` | JSON | launch 层结构化摘要（targets/max_rounds/study…） |

唯一写点：task_manager `_persist_task` → `upsert_task`（每次状态迁移整行 upsert）。
跨进程可见性全靠库行——dashboard / MCP / TUI 三进程各自的内存 TASKS 互不可见，列表 = 本进程视图 ∪ `query_tasks`。

#### `trials`

| 列 | 类型 | 说明 |
|----|------|------|
| `study` + `idx` | 联合 PK | study 名 / trial 序号 |
| `work_dir` | str | 该 trial 的 work-dir 绝对路径 |
| `target` / `seed` | — | 多目标语义补登记 |
| `status` | str | success / failed / timeout / error … |
| `metrics` | JSON | 目标指标（conv_rounds 等） |
| `params` / `search_fp` / `search_params` | JSON/str | 试过的参数与搜索空间指纹 |
| `returncode` / `error` / `elapsed_s` | — | 执行明细 |

唯一写点：study.py 完成一个 trial 即 `upsert_trial_record`（断点续跑读表；旧世代 trials.jsonl 仅首次空表时一次性导入）。

### 2.3 预测器域

#### `probes`（模型防御指纹）

`model`(PK) + `fingerprint`(JSON, per-seed Elo 向量) + `seed_methods`(JSON) + `n` + `computed_at`。
BlendPredictor 用指纹相关系 数做相似度加权池化；也是缓存键的一部分。原 `state/probes.json` 已表化（单事务 upsert，跨进程竞态消失）。

#### `predictor_cache`（真 LRU 登记）

`key`(PK，缓存文件名去 .pkl——**文件名即指纹**) + `size` + `created` + `last_hit` + `hits`。
命中/落盘时记 `last_hit`；`cache prune --max N` 先对账再按 `last_hit` 淘汰。blob 本体仍在 `output/predictors/*.pkl`。

### 2.4 control 域（三省制）

| 表 | PK | 说明 |
|----|-----|------|
| `ctl_events` | 自增 id | 文牍事件流（append-only 单事务 INSERT）：plan_started / step_* / plan_finished，`detail` JSON。审计与 `get_plan_context` 时间线重建的真相源 |
| `ctl_plans` | `id` | Plan 全量：`payload` JSON 即完整 Plan 结构（步骤/能力/参数），写穿缓存（内存 `_PLANS` + 库行） |
| `ctl_plan_meta` | `plan_id` | Plan 列表视图（intent/status/最后事件时间），`list_gazettes` 用 |
| `ctl_tickets` | `plan_id`+`step_id` | 门下省封驳令——库化后**重启不丢**（安全语义） |
| `ctl_queue` | 自增 id | Plan 执行队列内容：`PlanQueue` 构造时回填 queued 行（重启恢复），done 行滚动清理保留最近 20 |
| `ctl_workspaces` | `name` | fork 工作区索引（merged/merged_at/merged_to 供延迟 GC） |
| `ctl_env_snapshots` | `name` | .env 快照索引（`keys` JSON；.env 本体仍是文件） |

不可库化的内存态（有意保留）：confirm token 的零参闭包、bus 订阅/同步派发、`_SESSIONS` 会话对象。

## 3. 卫星库

| 库 | 创建者 | 内容 |
|----|--------|------|
| `output/workspaces/<n>/catalog.db` | fork（sqlite backup API 从全局库 clone） | 该工作区自己的全部表；跑完经 `merge` 把观测 upsert 回全局 |
| `<work-dir>/catalog.db` | `rebind_to_workdir`（HPO trial / `--work-dir` 隔离） | 同上；进程内所有存储调用自动路由到它 |

路由规则：`db_for(runs_root)`——全局 runs 根 → `output/state/catalog.db`，其他根 → `<根>/catalog.db`。

## 4. 文件产物（不入库，按角色）

### run 目录 `output/runs/<ts>/<target>/`

| 文件 | 角色 |
|------|------|
| `runner_report.json` | 人读制品；finalize_run 的 metrics 来源 |
| `security_tree.json` / `security_report.md` | 人读制品（看板渲染 / 用户阅读） |
| `attack_results.jsonl` | 攻击明细（含响应原文）；报告树、预筛 ML 训练语料 |
| `state.json` | tracker 快照（phase 2 续跑 / workspace fork 源） |
| `allergy.json` / `cluster_security_analysis.json` | 阶段产物 |

### 全局目录

| 路径 | 内容 |
|------|------|
| `output/state/safe_twins.jsonl` | 安全孪生集（append 流，10MB 锁内轮转） |
| `output/state/prescreen_model.joblib` | 预筛 ML 模型（`cache clean model_state` 可重训） |
| `output/cluster/` | feature/embedding/cluster 三缓存 + report/matrix |
| `output/predictors/*.pkl` | BlendPredictor 缓存（文件名即指纹） |
| `output/tasks/*.log` `.progress.jsonl` | 任务日志/进度流（状态在库，文件只是通道） |
| `.env` | 连接配置（唯一权威；docker 副本 `output/.env.bak`） |
| `output/.trash/` | 软删除回收站（按时间戳分目录，保留 OUTPUT_DIR 相对结构） |

## 5. 生命周期与维护命令

| 命令 | 作用 | 触及 |
|------|------|------|
| `llmsec-manage storage reindex` | 全量重建 runs 登记 | `runs` 表 |
| `llmsec-manage storage verify` | 登记与目录一致性检查 | `runs` 表 |
| `llmsec-manage storage gc-tasks` | 终态任务三件套软删 + 删行 | `tasks` 表 + `output/tasks/` |
| `llmsec-manage cache list / clean` | 缓存类别列出/清理 | predictors / feature_cluster / model_state |
| `llmsec-manage cache prune --max N` | 预测器真 LRU 修剪 | `predictor_cache` + pkl 文件 |
| `llmsec-manage storage backup-r` | 库备份（sqlite backup API，WAL 安全） | catalog.db |
| `llmsec-manage snapshot export` | 快照导出（库副本 → `output/snapshots/<ts>/`） | catalog.db |
| `llmsec-manage merge` | 工作区/历史 run 观测合并进全局 R | `observations` + `runits` |
