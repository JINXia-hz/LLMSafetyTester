# 攻击集导入对接指南

> 面向外部产地的攻击集贡献者：**不要求交出生成代码**，产物走导入通道进来即合规。
> "散落多源"在此被降级为一个接口问题——契约 + 通道 + 体检。

## 一分钟版

```bash
# 1. 自检（建议提交前本地跑）
python -m llmsec.attacks.validate your_file.jsonl

# 2. 导入（dry-run 先看报告，--yes 落盘）
llmsec-manage attacks import --file your_file.jsonl --source your_source
llmsec-manage attacks import --file your_file.jsonl --source your_source --yes
```

产物落盘 `attacks/imported/<source>.jsonl`。评估侧用法与本地数据集一致：
`llmsec --input attacks/imported/your_source.jsonl ...`。

## 契约字段（`llmsec/attacks/schema.py`）

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `id` | ✅ | 非空，全局唯一 | 与既有三个 id 空间（attacks/、cleaned/、imported/）不得冲突；导入通道自动检测 |
| `method` | ✅ | 非空 | 攻击方法/模板族名。**勿逐条唯一**（曾出现 `tpl-0000` 式写死，聚合尽失）|
| `prompt` | ✅ | 非空白，≤100k 字符 | 可直接发给目标模型的完整文本 |
| `harm_type` | 建议 | 六类+other | violence/hate/fraud/privacy/self_harm/illegal/other；不确定才用 other |
| `source` | 自动 | SOURCES 枚举 | import 命令的 `--source` 登记，新产地先在 schema.SOURCES 注册 |
| `category` / `category_name` | 可选 | | 分类体系位置 |
| `math_problem` / `expected_answer` | 可选 | | 越狱税探针（不注可省，评估自动跳过） |
| `evolved` / `operator` / `parent_id` / `generation` | 系统预留 | | 进化血统（自适应攻击进化用，导入数据勿填） |

其余字段（如 harmbench 的 `behavior_id` 等）原样透传，不做白名单限制。

## 体检会查什么

`python -m llmsec.attacks.validate`（或 `llmsec-manage attacks health`）：

- 契约违规（缺必填/空 prompt/超长）—— error 级
- `harm_type` 分布与 other 占比（越高元数据越不可用）
- **mojibake 检测**：UTF-8 被 GBK 误读的特征字符（历史教训：2,090 条入库时带乱码）
- 文件内重复 prompt / 重复 id；跨文件重复组
- `method` 基数（接近总条数 = method 逐条唯一，聚合失效）

## 已知历史坑（新产地避坑清单）

1. **编码**：产线脚本在 Windows 上用系统默认编码读 UTF-8 文件 → GBK 双重编码乱码。读写一律显式 `encoding="utf-8"`。
2. **method 唯一化**：把序号拼进 method（`tpl-0000`）导致无法按方法聚合。序号放 `id`，method 写模板族名。
3. **harm_type 全 other**：不标注危害类别，维度分析失效。至少粗标六类。
4. **id 重排**：合并多个数据集时重排 id（曾发生在 all_merged），跨文件不可连接。id 一经发放永不改变。

## 产地登记

新 `source` 需先加入 `llmsec/attacks/schema.py` 的 `SOURCES`（一行），保证 id 空间有主、体检可按产地归因。
