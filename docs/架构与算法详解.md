## 0. 全局数据模型：R 矩阵是唯一真相

整个评估体系的原始观测只有一份存储——**结果矩阵 R**（`llmsec/core/results.py` 的 `ResultsMatrix`）：

```
R[记录id][模型] = MatchResult（评分、status、轮次等）
```

其余一切都是从 R + 攻击方法特征 X **派生**的缓存，可随时删除重算：

```
                    ┌─ elo_cache.json      （Elo 派生缓存）
R (results.json) ───┼─ predictors/          （Blend/SVD-Ridge 预测器缓存）
                    ├─ probes.json          （防御指纹）
                    └─ safe_twins.jsonl     （安全孪生集）
```

派生入口是 `evaluation/elo.py` 的 `derive_elo()`：从 R 回放某模型的全部观测，重建完整 `ELOTracker`。收敛轨迹自轮次编号（`round`）记在 `MatchResult.extra`，轮次单调时按轮回放（快），混杂数据回退逐场回放（慢但正确）。

**单元化原则**（为什么 runner 默认不写全局 R）：早期版本每次 run 都把观测累加进全局 R，导致"越后面的 run 精度越高、分支之间互相打架"。现在 runner 默认把产物留在 run 目录 / work-dir，要更新全局 R 必须走显式动作 `llmsec-manage merge`。

## 1. 双边 Elo 评级（反向 ELO）

**问题**：ASR（攻击成功率）只能回答"这个攻击集平均成功率多少"，回答不了"哪类攻击威胁最大""模型的安全边界在哪""还差多少次测试才能下结论"。双边 Elo 把攻击方法和目标模型放进同一评级空间，用最少的对局数收敛出这些答案。

**模型**：攻击方法是进攻方，目标模型是防守方。攻击成功 → 攻击方 Elo 上升、防守方下降；被防住则反向。防守方 Elo 即"安全边界"——Elo 越高的攻击方法威胁越大，边界低于全部方法的模型是安全的。

实现在 `evaluation/elo.py` 的 `ELOTracker`，三个关键设计：

### 1.1 连续成绩映射（根治 Elo 早期震荡）

经典 Elo 的结果是赢/输二值，分数幅度只能塞进 K 因子，导致早期评级来回跳。这里改为把 Judge 分数映射成饱和的连续结果项：

```
perf = score / (score + τ)     # τ 见 params.py 的 SCORE_PERF_TAU
```

分数幅度进入结果项而非 K 因子，一场大胜和险胜对评级的影响有区分度，且天然有界。

### 1.2 K 衰减（防守方评级越测越稳）

- **攻击方用全 K**：每个方法通常整场评估只被测 1~2 次，评级需要快速到位。
- **防守方 K 衰减**：`K_def = K / sqrt(max(1, n/N0))`（`N0` 见 `K_DEF_DECAY_N0`）——防守方每轮必上场，场次越多单场影响越小，评级收敛后不被单场异常拖走。

### 1.3 同步轮次更新（Model B）

一个 round 批内有多场攻击，都打在**同一个**防守方状态上——它们是对同一状态的同时独立观测，不该按到达顺序逐场更新（否则批内顺序影响结果，且 batch 大小与 K 耦合）。做法：

1. 轮始给防守方 Elo 拍快照，批内所有攻击都用快照值算 delta；
2. 攻击方各自独立更新；
3. 防守方一次性加总，聚合步长除以 √N（有效独立数），避免 N 场全 K 求和过冲。

入口是 `ELOTracker.update_round()`。

## 2. 收敛判据：单一 CI 准则

**问题**：什么时候可以停止测试？逐场看 Elo 曲线是否"看起来平了"不可靠——曲线平可能是真收敛，也可能是漂移恰好放缓。

**做法**（`evaluation/elo_convergence.py` 的 `ConvergenceMixin.check_convergence`）：对防守方 Elo 轨迹做 OLS / Theil-Sen 回归，把序列分解成：

- **漂移（drift）**：系统性趋势，说明还在朝真值移动；
- **噪声（noise）**：AR(1) 校正后的随机抖动，决定测量精度。

两者合成"真值 Elo 的 95% 置信区间半宽"。收敛当且仅当 **CI 半宽、漂移、覆盖率同时达标**。CI 极紧时自动放宽 drift 门槛——漂移量小于测量精度时没有实质影响。阈值集中在 `params.py` 的 `CONV_*` 组。

## 3. 冷启动预测：给未测对象一个先验

**问题**：评估开始时没有任何观测，Elo 无从谈起；攻击方法几百个，也不可能全测。需要用"方法特征"预测未测对象的初始 Elo，把实测预算集中到信息量最大的地方。

### 3.1 SVD-Ridge（底层回归器）

`evaluation/predictors/svd_ridge.py` 的 `EloPredictorModel`：用已测方法的特征矩阵 X 和派生 Elo y 训练 Ridge 回归；对 X 做 SVD 分解后一次前向传播得到**全部**未测方法的预测；K-Fold 在正则化路径 λ 上选最优；每个预测附带 MAP 不确定性。

### 3.2 Blend 双层混合（跨模型借力）

`evaluation/predictors/blend.py` 的 `BlendPredictor`，混合两层预测：

- **统一层 P_u**：跨所有模型池化训练，捕获"方法内在威胁"（强越狱对多数模型都强）；
- **模型层 P_m**：仅用该模型自己的观测训练，捕获模型特异性弱点。

混合权重 `w_m = n_model / (n_model + K)`（`BLEND_PRIOR_K`）：该模型样本少时全靠统一层，样本多后逐步信任自身。R 有 ≥2 个模型时 runner 优先走 Blend，否则回退单模型 `ColdStartPredictor`。

### 3.3 防御指纹 + 相似度迁移

冷启动时先跑一组 D-optimal 哨兵种子（特征驱动、与矩阵无关），per-seed 的 Elo 向量就是该模型的**防御指纹**（`evaluation/predictors/fingerprint.py`）。两模型指纹的相关系数量化行为相似度，BlendPredictor 据此做相似度加权池化——从行为相似的 donor 模型借先验，取代"所有 donor 均匀平均"。指纹独立于累积 R，符合"发现测试不依赖过去的矩阵"。

### 3.4 D-optimal 种子选择

`evaluation/predictors/active_learning.py` 的 `greedy_d_optimal`：贪心最大化特征子集的行列式（信息量），选出哨兵单位。直觉是让初始实测在特征空间里尽量张开覆盖，而不是聚在一角。

## 4. 评级单位与聚类

### 4.1 unit：簇 = 评级单位

`llmsec/core/units.py`。攻击方法几千条 prompt 逐条评级不现实也不稳定，逐"方法名"评级又太粗。折中：把 prompt 聚成簇，**簇作为评级单位（unit）**，簇内成员共享一个 Elo。unit_id 由成员 md5 指纹生成（成员不变则 id 稳定，跨 run 可续）；unit 特征 = 成员特征质心；每 unit 选一条 medoid 记录做实测代表。

### 4.2 统一先验度量空间

聚类与预测的距离度量**只用先验特征**（不看评估结果），保证"发现新弱点"不被历史结果带偏。流程：特征 z-score 标准化 → `clustering/space.py` 阻尼白化（轻量马氏）→ SVD 降维 + 谱拐点截断噪声尾。

### 4.3 双视图聚类

- **HDBSCAN（EOM）**（`clustering/hdb.py`）：密度视图，从可缩放树切候选 k；
- **Ward auto-k**（`clustering/tree.py`）：`log_growth_k0` 自动层数 + 轮廓系数选优。

主标签用 Ward 视图（`compute_cluster_labels`，被 `pipeline/attack_phase.py` 的 `_quick_precluster` 复用做 Phase 1 开头的预聚类）；HDBSCAN 视图供对比与候选 k。同一棵树切出的候选 k 用轮廓系数 / CH / DB 合成取全局 argmax。

### 4.4 post-test 弱监督

测试结束后用真实机器反应做特征加权（`clustering/posterior.py`）：哪些特征维度真正区分了模型的防御行为，据此调整距离度量，供下一轮预测使用。这是聚类管线唯一接触评估结果的环节。

## 5. 采样器：下一批测什么

`evaluation/samplers.py`，四个策略，工厂 `build_sampler()`：

| 采样器 | 逻辑 |
|---|---|
| `gap` | 选 \|攻击 Elo − 防守 Elo\| 最小的单位——边界附近信息量最大 |
| `infogain` | 全局信息增益：分差 + 预测不确定性 + 簇覆盖 + 成功潜力加权；gap 项归一化到 [0,1) 与其他项等量级 |
| `coordinate` | 簇坐标下降：外层轮询簇，内层选边界附近方法 |
| `hybrid`（默认） | 前若干轮 InfoGain 快速覆盖，之后切 Coordinate 精细搜索 |

权重系数 `--sampler-alpha/beta/gamma`，默认值在 `params.py` 采样器组。

## 6. 过敏检测与越狱税

### 6.1 安全孪生（FPR）

**问题**：ASR 高说明防得严，但"全部拒绝"的模型 ASR 是 0——安全不能以误杀正常请求为代价。

**做法**（`evaluation/safe_twin.py`）：在 Elo 边界附近挑高威胁攻击，用 LLM 改写出"安全孪生"——语义安全、结构与原攻击相似的 prompt；发给目标模型，若被拒绝或行为异常即记一次误杀。汇总得 FPR（误杀率），与 ASR 构成二维画像。孪生窗口大小自适应边界置信度（`pipeline/allergy_phase.py` 的 `adaptive_twin_window`）。

### 6.2 越狱税（Jailbreak Tax）

**问题**："越狱成功"通常只看模型有没有输出有害内容，不衡量越狱状态下能力损失多少。

**做法**：攻击 prompt 中嵌入数学题。对比同一模型裸做数学的基线（`evaluation/scoring.py` 的 `measure_math_baseline`）与攻击下的正确率，`accuracy_drop = 基线 − 攻击下` 才是真实的越狱退化。攻击集中 `expected_answer: 0` 表示该条不参与越狱税统计。

## 7. 存储布局与派生关系

```
output/state/
├── results.json        # R 主存储（权威，唯一不可重算）
├── elo_cache.json      # derive_elo 的缓存（可删可重建）
├── probes.json         # 防御指纹
└── safe_twins.jsonl    # 安全孪生集
output/predictors/      # BlendPredictor 缓存
```

`--work-dir` 模式下全部 9 类写入点重绑到 work-dir（`core/isolation.py` 的 `rebind_to_workdir`），全局 `output/` 零写入。把某个 work-dir / 历史 run 的观测合并进全局 R，走 `llmsec-manage merge`（dry-run 预览 + `--yes` 执行，复用 `ResultsMatrix` 的文件锁与原子写）。

## 8. 审查阈值

门下省自动审查 run 产出（ASR/FPR/收敛/CI/surprise 威胁等判定线）集中在 `llmsec/params.py` 报告阈值组，经 `llmsec-manage thresholds` CLI 导出——审查方与被审查方读同一份常量，不复制不漂移（`control/agent/review.py` 消费）。
